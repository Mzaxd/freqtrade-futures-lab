# Dry-run 计划（候选策略确定后执行）

> 目标：在不动真实资金的前提下，度量"回测 → 模拟盘"的执行偏差。任何实盘行为都必须先通过本计划且获得用户**明确书面授权**。

## 1. 启动方式（本地，无 API key，dry-run 模式）

```bash
cd freqtrade-futures-lab
.venv/bin/freqtrade trade \
  --userdir user_data \
  --config user_data/configs/config_futures.json \
  --strategy <最终候选策略> \
  --db-url sqlite:///user_data/tradesv3.dryrun.sqlite \
  --logfile user_data/logs/dryrun.log
```

配置中 `dry_run: true`，不配置任何 API key，绝不连接实盘账户。

## 2. 最短观察期

- **至少 4-8 周**，期间不改参数（参数冻结，与回测一致）。
- 覆盖至少一次显著波动期后再评估；若全程横盘，延长观察期。

## 3. 每周记录（脚本化，保存到 `user_data/reports/dryrun_weekly/`）

| 项目 | 说明 |
|---|---|
| 信号数量与方向 | 与同期回测信号逐一对照 |
| 成交价 vs 信号K线收盘价 | 滑点估计（市价单） |
| 实际成交手续费 | dry-run 使用交易所真实费率表 |
| 资金费率实收实付 | 与回测所用数据对照 |
| 持仓时间、止损触发 | 与回测分布对照 |
| 机器人宕机/重启次数 | 运行风险记录 |

## 4. 停止条件（任一触发即暂停并复盘）

- 回测 vs dry-run 同期收益率方向相反且差异 > 2 个 ATR 止损单位；
- 平均成交滑点 > 0.1%（即超过压力测试假设的 2 倍）；
- 出现回测中从未出现的退出类型（如强平）；
- 连续异常重启或数据断流。

## 5. 实盘前检查清单（全部满足才可向用户申请授权）

- [ ] 我能向用户用三句话讲清策略逻辑与其失效场景；
- [ ] 已知历史最大回撤、最差月份、最长回撤持续期（来自样本外+压力测试报告）；
- [ ] 每笔交易有 ATR 止损，仓位有硬上限（≤35% 权益保证金、杠杆 ≤3x）；
- [ ] 已考虑：交易所宕机（止损单不在交易所侧 → 需迁移 stoploss_on_exchange）、极端行情插针、资金费率极端值；
- [ ] 投入资金为可全损资金，单笔风险 ≤1% 权益；
- [ ] **用户明确授权**（缺此条绝不实盘）。

## 6. 免责

Dry-run 结果与未来实盘仍会有偏差（流动性、队列位置、部分成交）。本计划不构成任何盈利保证。
