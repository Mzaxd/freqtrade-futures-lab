# 迭代日志（iteration_log.md）

> 每轮一个假设；未改善即回滚；全部 git 留痕。数据纪律：IS=2021-01→2022-12（拟合/开发），VAL=2023-01→2024-12（选择/验证），最终样本外=2025-01→2026-09（开发期绝不查看，仅最终评估一次；该段在上轮研究中曾作为聚合块被查看过一次，已在 00_diagnosis.md 披露）。

## 第 1 轮（iter-1）

**目标**：建立状态识别层 v1（规则基准 + 4 态 HMM 原始特征），验证"能否从数据中识别市场状态"。
**执行**：实现 `regime_detector.py`（HMM 仅 IS 拟合、自实现因果前向滤波）；VAL 评估准确率/滞后/分布。
**结果**：
- 样本内指标：HMM 拟合似然 -139565.7（52,488 训练行）
- 验证集指标：规则 acc 23-50%、HMM acc 30-68%，全部**低于多数类基线（77-80%）**；HMM"混乱"态占比 0.4%（退化）；滞后 22-38h
- 状态识别：分布违反 [5%,70%] 约束；标签设计缺陷（range 占 80% 使基线虚高）
**与上一轮对比**：—（首轮基线）
**结论**：不通过 → 重构评估标签（窗口内分位数）并进入 v2
**失败原因**：原始特征非平稳 + 标签不平衡使准确率指标失真
**下一步**：v2 = 3 态 HMM + 规则覆盖层 + 平衡标签 + 更快窗口（12h/72h）

## 第 2 轮（iter-2）

**目标**：修复状态退化与标签失真（假设：更快特征 + 分位标签 + 覆盖层可解决）。
**执行**：重构 `regime_detector.py` v2；重拟合；VAL 评估。
**结果**：
- HMM v2：BTC acc4 61.6%（平衡标签，基线 68.7%）仍低于基线；**trend_up 占比 0.09% 仍退化**；滞后改善至 15-17h
- 规则 v2（IS 分位阈值）：acc4 57.5-63.4%，仍低于基线；滞后 20-36h
- 状态分布：HMM range 78-84% 越界
**与上一轮对比**：滞后改善 / 准确率与分布恶化
**结论**：不通过 → 关键诊断：**2021-22 拟合的原始尺度使 2023-24 恒被判为"震荡"（特征非平稳）**
**失败原因**：特征量纲依赖市场时代
**下一步**：v3 = 无量纲自归一化特征（mom_z 动量 t 统计量、vol_ratio 波动比率）

## 第 3 轮（iter-3）

**目标**：无量纲特征解决跨时代可比性（假设：mom_z + vol_ratio 使状态分布健康且滞后达标）。
**执行**：改特征并重拟合 HMM v3；规则版同步改 t-stat 阈值；IS 阈值扫描 {0.75,1.0,1.25,1.5}（合规：仅训练窗）；冻结 thr=1.25；VAL 评估一次。
**结果**：
- IS 扫描：thr=1.25 acc3=0.597 且分布健康（13.6/9.6/65.8/11%）；thr=1.5 acc 更高但 range 73% 越界 → 弃
- 冻结版 VAL：acc4 49.0-50.5%（线 50%）⚠️、acc3 58.3-58.9%（线 60%）⚠️、滞后 8-14h（2.0-3.5×4h）✅、分布 14/9/65/12 ✅
- 经济性（前瞻 72h 条件收益）：trend_up 三对 +0.94%~+1.52%（t=8.7-11.4）强显著；trend_down ETH/SOL 方向正确、BTC 失效
- HMM v3：分布恢复但 acc4≈36% → 淘汰 HMM 路线，采用规则 v3
**与上一轮对比**：滞后、分布、可解释性、稳健性（零拟合参数除 IS 阈值）全面改善；准确率仍差 1-2pp
**结论**：有条件通过（检测器冻结为规则 v3；准确率子标准未达，作为已知局限记录）
**失败原因**：—（准确率缺口如实记录）
**下一步**：进入第二层（3 个独立子策略）与路由增益测试——用 6.4 的功能标准检验检测器是否产生交易价值

## 第 4 轮（iter-4）路由集成 v1

**目标**：三层架构首次集成（breakout/趋势空/1h MR + 路由）。
**结果**：IS：-31.97%（398 笔，MR -1516、breakout -1834、TS +153）。IS 独立基线：MomentumBreakout -29.95%、TrendShort +1.52%、MeanReversion -92.23%。
**结论**：不通过。突破与 1h MR 双双结构性失败。
**下一步**：iter-5 换趋势腿为 EMA 引擎。

## 第 5 轮（iter-5）trend_up 腿换 EMA 趋势引擎

**结果**：IS：-17.32%（257 笔；MR -1723 仍主导；trendlong 仅 13 笔——事件∧状态几乎不相交；TS +149）。
**结论**：不通过（较 iter-4 改善但趋势腿饿死、MR 失血未止）。

## 第 6 轮（iter-6）MR 移到 4h（锚定止损、中轨止盈、无追踪）

**结果**：IS：-5.67%（仅 24 笔全为 MR，WR 8.3%；趋势腿 0 笔——MR 占用交易对名额堵死趋势入场）。
**结论**：不通过。发现仓位占用冲突与"事件入场"的结构问题。

## 第 7 轮（iter-7）状态驱动的仓位生命周期

**改动**：趋势入场改电平条件；状态失配即出场（turbulent 除外）。
**结果**：IS：-3.30%（76 笔；TL 31笔 +8、TS 16笔 +190、MR 29笔 -528 WR 3.4%）。
**结论**：不通过但接近盈亏平衡；MR 为唯一失血点。

## 第 8 轮（iter-8）MR 拒绝证据入场（z 回穿带内）

**结果（初跑）**：IS +43.5% —— **数字不自洽（MR WR 7.4% 却 +3575）**，排查发现两个 bug：① `use_exit_signal=False` 导致 `custom_exit` 从不被调用（freqtrade 仅在该开关为真时调用 custom_exit），一笔 SOL 多单被 minimal_roi=10000% 上限兜住，+3955 为虚假利润；② `int(NaN)` 抛异常使信号退出静默失效。
**结果（修复后重跑，真实）**：IS **-7.10%**（1207 笔，1151 笔 regime_mismatch_exit——状态阈值附近高频震荡换仓，双边 taker 磨损）。
**结论**：不通过；bug 修复为必要工程修正，不改变迭代判据。
**下一步**：iter-9 回第一层：状态序列驻留平滑（消除阈值噪声翻转）。
