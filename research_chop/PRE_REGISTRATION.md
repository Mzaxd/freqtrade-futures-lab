# research_chop 预注册包 — 震荡期收益捕获增量线（2026-11-04）

> 本线是对已冻结 research_ab 包的**增量研究**：冻结包（3 币 / A=OPT9_Recycle@1.21 钱包70% /
> B=MomRegime 钱包30% MOT3 / 红线 -20%/30d）本身不变，A/B 入场逻辑继续不可动（falsified-direction）。
> 所有新增只允许两类：(a) 新 sleeve C 及其变体；(b) A 的 **sizing 层** regime overlay（不动信号、不动止损逻辑）。

## 1. 问题定义

冻结 AB 的亏损集中在震荡期（已知锚点：2026-02-15→08-10 AB -27.6%、峰谷 -30.3%；A 的 66 次合规止损
集中于此）。本线目标：量化震荡期可捕获收益的上限，并测试四条路径。

## 2. 门控定义（全部因果，参数原样复用 regime_detector.py 规则核，禁止调参）

特征（1h，逐 pair 自身数据，全部尾随窗口）：
- `ret_1h = log(close).diff()`；`vol_12h = ret_1h.rolling(12).std()`
- `mom_72h = log(close).diff(72)`；`mom_z = mom_72h / (vol_12h * sqrt(72))`
- `TR = max(h-l, |h-pc|, |l-pc|)`；`atr_pct = TR.rolling(14).mean()/close`
- `atr_pct_rank = atr_pct.rolling(720, min_periods=240).rank(pct=True)`

状态（= regime_detector.py rule_states 原样）：mom_z≥+1.25→up(0)；≤-1.25→down(1)；否则 range(2)；
overlay：atr_pct_rank≥0.90→turbulent(3)。

**门（预注册；分派前已做锚窗口验证，见 §2.1）：**
- **G1_momz**：`|mom_z| < 1.25`（方向缺失，任意波动）——**阴性对照**（验证发现其占有率在趋势期
  与震荡期同为 ~73-75%，不判别，预期表现 ≈ 全局 risk×0.5，即已知结果）
- **G2_violent**：`|mom_z| < 1.25 AND atr_pct_rank ≥ 0.90`（崩盘当下高波震荡；对 C 引擎是
  单位时间波动最厚的窗口）
- **G4_persist**：过去 240h 内 ≥90% 的小时满足 G1（持续方向缺失；网格经典栖息地）。
  初版"state==2 连续 240h"不可达（turbulent overlay 逐时打断，占有率恒 0），改分数定义，迭代在此披露
- **G3_cluster**（**R3 主假设**）：交易失败密度门——A 侧单边 D 天内 N 次止损 → 该边风险减半
  （或暂停），直至该边出现盈利单；N∈{2,3,4}×D∈{14,30} IS 网格选择。思想 = 3 币密度重标定的 P2。

## 2.1 锚窗口验证（分派前完成，全部披露）

已知出血窗 2026-02-15→08-10 与趋势主场 2021-11→2022-11 的门占有率（BTC）：
G1 两窗 0.755 vs 0.730（**不判别**）；G2 出血窗仅 0.030（低于常年 7-9%，ATR 排名抓的是崩盘当下
而非其后 6 个月温和震荡）；G4 出血窗 BTC 0.014 / SOL 0.094（币间分裂：2026 震荡是"反复失败的
反弹"，mom_z 频繁短暂越限再失败，非持续安静缺失）。

**结论**：市场特征门（G1/G2/G4）对 A 的出血模式系统性滞后/误判；唯一能直接识别"反复突破失败"
的是自指的 G3 失败簇门——与 P2 在 12 币上唯一有效的事实互相印证。故 G3 为 R3 主假设，G1 降级
为阴性对照。C1/C2 无法跨容器读 A 的成交，只能用市场门：**g2 与 g4 双门实现、IS 上限高者入选，
OS 只跑选中门**（决策规则先于任何 OS 运行注册于此）。

披露：锚窗口验证使用了 2026（属 OS 窗）的描述性事实——该窗口解剖来自上一会话已披露的熊市解剖
分析，非本轮新看 OS 结果；所有门/参数的选择决策仍仅以 IS 2021-2023 为准。

因果性：t 时刻标签只用 ≤t 收盘数据；用于 t+1 开盘及之后的决策。回测内实现必须复用 WS3 验证过的
`get_pair_dataframe` + 严格因果切片模式（禁止 `get_analyzed_dataframe`，1000 根截断 bug）。

## 3. 数据与口径

- 宇宙：BTC/ETH/SOL（Binance USDT-M 永续）；窗口 20210101-20260912；数据至 2026-09-14。
- 手续费：0.0005/边（与 OPT7_config_12p.json 一致）；网格/模拟一律同口径，maker 也按 taker 计（保守）。
- IS = 2021-01-01~2023-12-31（设计/选门/调参唯一允许窗口）；OS = 2024-01-01~2026-09-12（披露窗，只裁决）。
- 基线：A 侧 = ARL_2x（OPT9_Recycle@1.21, lev2）；B 侧 = mtm_daily_B3.csv 日曲线；
  A 参考曲线 = mtm_daily_A3.csv（OPT4 基，用于出血归因，须披露口径差异）。
- 组合口径：AB+C 拼接用 ws2_analysis.py 方法（日频固定权重、收益拼接）；wC ∈ {0.05, 0.10, 0.15}，
  从 A/B 按比例让渡；A 内 overlay（R3）不改变 70/30 结构。

## 5. 网格方法学（C2 专用，预注册）

- 数据：5m feather；网格仅在门开时段激活，门关立即市价清库存（实现门滞后成本）。
- 成交假设（保守）：限价买单仅当后续 5m low **严格低于** 挂单价才算成交（穿越成交，触不算）；
  卖单对称。全部按 taker 0.0005 计费。
- 库存成本：8h funding（funding_rate feather 实际值，按持仓方向收付）；杠杆上限 2x；
  逐根检查强平价（维护保证金率 0.5%），触强平=该窗口实现全部亏损。
- 网格参数：层数/间距在 IS 2021-23 网格选择，OS 只跑选中点；披露对成交假设的敏感性
  （touch vs cross 两种口径的差 = 成交假设风险敞口）。

## 6. 交叉核验规则（调度员执行）

1. **上限核验**：若 C0 的 naive 上限（扣费后）≤0 而 C1/C2 在 OS 显著为正 → 过拟合警报，
   C1/C2 结论降级为"不可采信"，需说明超额收益来源。
2. **门重叠核验**：C1/C2/R3 使用的门必须与 C0 标签 CSV 逐点一致（抽样比对 ≥ 3 个窗口）。
3. **成本核验**：C1/C2 的笔均费用占比必须披露；若 OS 笔均净利 < 2×费率 → 边缘过薄，标注。
4. **红线复核**：任何 AB+C / R3 组合在 OS 的 MC p95 30dDD 恶化超过基线 2pp → 否决该配置。
